# Storm Disaster Database (dataset paper)

Self-contained: its own code, uv environment (`.venv`, `pyproject.toml`, `uv.lock`), data (`datasets/`), keys (`secrets/`) and docs (`docs/`). Nothing is shared with `../github_chatbot_cyclones/`: no imports, no data, no outputs.

## Pipeline (run in this order)

One script per step of the paper's workflow figure (1 Download, 2 Clean, 3 Link, 4 Extract, 5 Build).

1. `dataset_download/run1_download_datasets.py` fetches raw data only (cached in `datasets/raw/<source>/`). Everything else is in `dataset_exp/`; `lib_cleans.py` puts `dataset_download/` on the import path for the raw files' paths.
2. `run2_clean_datasets.py` reads each raw file, keeps and renames only the columns the database uses, fixes types, cuts every source to 1990–2023 by its spec's `dated_by` column (`standardize()`) and expands the indicators to every country-year, to `datasets/clean/<source>.csv`; EM-DAT first, because Geo-Disasters' units are checked against it; `clean_geodisasters()` also writes each storm × country's area (`geodisasters_areas.gpkg`) and a row for every storm × country with its coordinate, if any (`datasets/linked/event_points.csv`). Nothing is linked here. Logs to `logs/`.
3. `run3_link_records.py`, on `run2`'s full tables (rerun `run2` first): each record's event area in `event_points.csv` (`link_areas()`: `area_source` `units` or `point_buffer`, `area_quality` the weakest grade of its units); IDMC / IFRC rows matched to EM-DAT storms (`link_sources()`, `matched()`: `disasterno`, `match_method`, `idmc_confidence` / `ifrc_confidence` on the source rows, only to a storm of the row's own country); cascades (Jäger's influences, `link_cascades()`) → `datasets/linked/cascades.csv`; every cleaned table cut to the storms' rows (`keep_storm_rows()`); best tracks (`match_tracks()`, CLIMADA wind fields as Eberenz et al. 2021, with IBTrACS's reported values; `run3_link_records.TRACK_SUBTYPES`) → `datasets/linked/track_features.csv` and `track_points.csv`. Logs to `logs/`.
4. `run4_extract_measures.py` → the event-area extracts per storm × country (rows and coordinates from `lib_cleans.storm_events()`), raw values first (the supplement (`../manuscript_dataset_storms/latex_big_earth_data/supplement.tex`: S1 each column's product and reduction, S1d the values left to users with their formulas)): `extract_gtsm()` (GTSM storm surge from the CDS, one request per variable and year, 3 at once, the ECMWF token in `secrets/cds_key.json`; `run4_extract_measures.GTSM_SUBTYPES`) → `datasets/linked/gtsm_features.csv`; then `extract_gee()` (Earth Engine, each subtype only its own layers, `LAYERS`, over the event's Geo-Disasters units in `datasets/clean/geodisasters_areas.gpkg`; a buffer around EM-DAT's point without units) → `datasets/linked/gee_features.csv` (resumable, deadliest first, checkpoint every 50 rows), split by `split_gee()` into the area's measured columns (`area_km2`, `buffer_km`, `area_land_frac`, `gee_date`), added to `event_points.csv`, and six entity tables (`exposure_features`, `weather_features`, `convection_features`, `wave_features`, `snow_features`, `dust_features`).
5. `run5_build_outputs.py`, from the storm context: `write_schema()` → `datasets/schema.yaml` (every CSV's primary and foreign keys from `lib_cleans.SCHEMA`, the extracts included); `check_keys()` (every primary key unique, every foreign key pointing at a row); `build_database()` → `datasets/outputs/storms.sqlite` (one table per CSV, its keys enforced); `build_graph()` → `datasets/outputs/storms.ttl.gz`, the RDF knowledge graph (Turtle; things as hubs: events, countries `owl:sameAs` Wikidata, tracks; GAUL units are values of the Geo-Disasters rows; statuses are plain values, defined in the data dictionary (`docs/data_dictionary.csv`); relations `hitCountry`, `influences`, `matchedTrack`; every row a node of its table's class with its values, typed dates and GeoSPARQL points; every class under one of eight main classes, `MAIN_CLASSES` (Event, Entity, SourceRecord, Location, Hazard, Exposure, Vulnerability, Cascade; `rdfs:subClassOf`); generated from `schema.yaml`, so a new table needs no code; with its vocabulary (QUDT units), SHACL shapes and VoID description; `docs/knowledge_graph.md`); the competency questions (`QUERIES`) run on both graphs and are released as `query1.rq`–`query6.rq`; `check_graph()` (SHACL on a sample of storms, the competency questions on the whole graph); the public graph without EM-DAT → `datasets/outputs/release/storms_public.ttl.gz`; and, from the complete tables, `build_release()` → `datasets/outputs/release/`: every table but `emdat`, keys only, EM-DAT's own points blanked, with `schema.yaml` (EM-DAT's licence forbids redistributing it). Users rebuild with their own EM-DAT export: `run1` → `run5`.

Statistics (`statistics/`) read the cleaned sources and links. The papers being written are `../manuscript_dataset_storms/latex_data_in_brief/data_in_brief.tex` and `../manuscript_dataset_storms/latex_big_earth_data/big_earth_data.tex`; keys are in `datasets/schema.yaml`, columns, statuses and gaps in `docs/data_dictionary.csv`, each journal's rules in `../manuscript_dataset_storms/docs/<journal>/rules/`, precedents' papers and code in `../manuscript_dataset_storms/docs/papers/`.

## Data Rules

- **Cached raw files.** Every raw file is cached in `datasets/raw/<source>/` and reused. Never refetch a cached source silently.

- **Absence is explicit.** Never write 0 or a default for a missing, failed or uncovered value; leave it empty and record the reason in a status (`<field>_status`, `<field>_gap`, `not_covered`). A bare null cannot tell "not covered" from "not obtained".
- **One place per rule.** Column choice, renames, types, signs (|x| for counts and amounts), units and dates live in `run2_clean_datasets.SPECS` and `standardize()`; `run1_download_datasets.py` only fetches.
- **Check a gap's cause before labelling it.** Look at the rows (coordinates, years, codes, coverage) instead of guessing; gaps here came from bad centroids, wrong EM-DAT years, land-only products and country codes that differ between sources.
- **Keys keep one name everywhere:** `disasterno` (EM-DAT id without the country suffix), `iso3`, `year`; role-named keys end in the key name (`from_disasterno`, `neighbour_disasterno`).
- **Admin-unit points: `point_and_area()`** (`lib_cleans.py`), never `.centroid`: centroids of island groups fall at sea and date-line units wrap the globe. Areas are geodesic, never Web Mercator, except in the cascades, which copy Jäger et al. (2025): overlaps in EPSG:3857.
- **One coordinate per event × country**, never one point reused for every country of an event.
- **Event area = the event's Geo-Disasters units in that country**, dissolved; a buffer only for an EM-DAT point (or units across the date line). Counts and areas (population, built-up) are mean densities × geodesic area, never a sum at a scale GEE may coarsen.
- **Land / sea from ESA WorldCover** (the area's land fraction; a point buffer shrinks until half is land), never a coarse land mask that misses small islands.
- **Weather over the event window** (EM-DAT dates ±1 day, at most 14 days; the start month when days are unknown), not monthly aggregates.
- **Storms only:** EM-DAT's 11 storm subtypes are the events (`lib_cleans.HAZARDS`, `hazard = storm`); every other disaster, coastal floods included (EM-DAT type Flood), stays in `emdat` without a hazard, as a cascade partner. IDMC / IFRC rows are storm rows by their own hazard types and match storms only (GLIDE excepted). The earlier all-climate scope is on the branch `climate-all-hazards`.
- **Each subtype gets only the measures that fit it**: `run4_extract_measures.LAYERS` (what is read; everything else `not_applicable`). Check a new measure's fit per subtype (table in the dataset paper's Methods) and its direction (pressure is its minimum, wind its maximum); thresholds are local percentiles of 1991-2020 where a raw value means different things in different places (the loss index's wind percentile).
- **Follow precedents.** Use the published method, read in its published code where there is one; depart only where following it is impossible or worse for storms, and state why in the paper's fidelity tables. Never copy a precedent's bugs, and do not discuss them. When precedents conflict, name the one followed and leave the other out.
- **No imputed dates.** A missing start day means the whole month (`event_dates()`); keep a time link only when its order is certain for every possible day, and mark it `_month` / `date_precision = month`. Exception: the cascades copy Jäger et al. (2025), whose code reads a missing start day as the 1st; `date_precision = month` marks those links.
- **No geocoding of place names.** Coordinates come from Geo-Disasters units or EM-DAT's own point; without one the event has no local context.
- **Null-aware string handling.** Never `str(x)` a value that can be NaN (`str(NaN)` is `"nan"`, which once matched every IDMC row without a GLIDE to one event); never `fillna("")` anything that is saved.

## Working Rules

- **Two versions of the paper, both active.** Data in Brief (`../manuscript_dataset_storms/latex_data_in_brief/data_in_brief.tex`, rules in `../manuscript_dataset_storms/docs/data_in_brief/rules/`) and Big Earth Data (`../manuscript_dataset_storms/latex_big_earth_data/big_earth_data.tex`, made from the Data in Brief text in Taylor & Francis's Interact layout, rules in `../manuscript_dataset_storms/docs/big_earth_data/rules/`; build with pdflatex and BibTeX with `template/` on `TEXINPUTS` and `BSTINPUTS`). Both cite `../manuscript_dataset_storms/latex_data_in_brief/references.bib`.

- **Talk first, implement later.** For a new design or a change of approach, explain the plan and wait for agreement before installing or writing code.
- **Packages: uv and the local `.venv` only.** `uv add <pkg>` (dev tools: `uv add --dev`) records it in `pyproject.toml` and pins it in `uv.lock`; `uv sync` rebuilds `.venv`; never `pip install` into the global Python. Prefer tried and tested open-source libraries over hand-written plumbing.

## Code Style

- **1 large function**, small functions for reuse or loops only
- 1 line comments for functions, avoid inline comments unless very necessary
- **Downloads and transforms are separate steps, in separate folders**: `dataset_download/run1` only fetches raw files (which never imports `lib_cleans`), `dataset_exp/run2` only cleans them (`lib_cleans.py`)
- **Every column in the data dictionary** (`docs/data_dictionary.csv`): a new column gets its row (table, kind, unit, meaning), its `_gap` and `_status` columns their own rows with the values each can take, or `run5` stops
- **Raw values first**: every extract stores each measure's raw ingredients in their own units (area maximum, minimum or mean over the window), then only the derived measures that cannot be rebuilt from them; what users can compute goes in the supplement's S1d (`../manuscript_dataset_storms/latex_big_earth_data/supplement.tex`)
- **Assertions for validation** — row counts, country counts, year ranges, keys
- **Paths use `Path(__file__).parent.parent`**
- No need of functions having extra parameters for flexibility, keep it simple and hardcoded
- No need of extra flexible approaches that will not be used. keep one single approach for each task
- No need of arguments for scripts for flexibility, keep it simple and hardcoded
- Never use classes. Use functions only. Classes are for objects with state, which we don't need here.
- Delete unused code, functions, and imports. Keep the codebase clean and minimal.
- avoid writing code always use existing libraries and functions and prioritze lower LOC. Don't reinvent the wheel
